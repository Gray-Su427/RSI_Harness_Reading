# P4 · 汇报 Q&A 一页速查

日期：2026-10-30｜负责人：P4（zgj）｜八问八答，回答按每条约 20 秒设计，彩排时实测调整。

**供稿状态**：以下八条由 P4（zgj）统一代拟；P1（xyc）、P2（zyc）、P3（szh）、P4（zgj）各分配两条确认责任，尚不代表全员已供稿或确认。主讲人使用“我们”前须完成组内确认。

| 问题 | 约 20 秒回答稿 | 确认负责人 |
|---|---|---|
| **1. 七篇怎么选，数量是否足够？** | 七篇覆盖经典 agent 设计、自修改、工业应用、自偏好和形式化保证，并加入一篇测量研究。目标是比较关键机制与反例。同行评审项仍待 venue 核验；最终按完整笔记和证据覆盖验收。 | P1（xyc） |
| **2. 目前到底读到哪一步，能说有十九篇了吗？** | 以 CP1 后的 CSV 为准：补齐前是十七篇、状态均为 skim；补两篇指定综述后是十九篇。中期交付是地图、初步判断和精读计划；七篇是精读名单，不能说成已经精读完成。 | P1（xyc） |
| **3. 多轮迭代为什么不一定是 full RSI？** | 关键是改进后的系统参与了什么：只搜索更好的任务产物，和改进负责下一轮更新的程序，不是一回事。我们会检查可编辑边界并保留作者原话，作者未界定时先记待核实，不按轮数升级标签。 | P2（zyc） |
| **4. AlphaEvolve 改算法，为什么还选入？** | 它提供进化搜索与外部评测的工业对照，可帮助区分“代码被优化”和“harness 自身被优化”。我们把它作为边界对照，不据此宣称已证明递归自改进，也不把它的案例增益当作 coding benchmark 排名证据。 | P2（zyc） |
| **5. 用 self-preference 选更新，会不会自说自话？** | 有这种风险，但采用自评不自动等于结果无效。要看候选选择和最终评测是否独立、是否有失效反例。RHO 泛读卡记录了偏好与测试最优不一致的案例，精读将核查其适用范围和单轮限定。 | P3（szh） |
| **6. SEVerA 有形式化保证，是否已解决安全问题？** | 保证要放回给定规格和定理假设里理解，不能扩展为所有行为都安全。它的 Learn 阶段还涉及权重更新，所以作为跨界对照。其作者也明确指出，功能规格不涵盖调用、token 或时间等资源预算。 | P3（szh） |
| **7. 能更新 harness，为什么不一定获得更高收益？** | 更新生成端和使用端是两种能力。P4 论文发现，在其模型与任务设置下，evolver 间增益相近，而 agent 获益并不随基础能力单调增加；弱模型可能不加载或不遵循更新。这不等于证明自进化无效。 | P4（zgj） |
| **8. 两周具体交什么，缺成本或代码怎么办？** | 按二、二、二、一分工：第一周形成七篇草稿，第二周补附录、交叉核对并完成方法比较。缺成本就暂不作效率结论，代码公开与结果复现分开登记。目标交付七篇完整笔记、三条证据和两至三个争议。 | P4（zgj） |
