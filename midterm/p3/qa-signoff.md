## 3. P3 已确认的两条（定稿，可直接背）

### ⑤ self-preference 会不会自说自话？

> 「有这个风险，而且 RHO 的作者自己给了反例：在 SWE-Bench Pro 上，最偏好的候选是 0.78，测试最高的是 0.85——**最偏好不等于最好**。它的机制保证的是「不劣于基线」：只有自评分为正才接受更新，所以不会掉到基线以下，但这不等于验证独立。精读要查的是两件事：自评与真值的一致率，以及候选选择和最终评测有没有物理隔离。」

- 出处：`notes/skim/arxiv-2606.05922.md`；`p3/rho-brief.md` 问 3、问 5
- 不要加的一句：「所以自偏好没用」——作者报告的是失效案例，不是机制无效。

### ⑥ SEVerA 有形式化保证，是否已解决安全问题？

> 「不能这么说。它的定理保证的是**给定规格下的功能正确性**——任意输入、任意参数取值都满足行为规格；但规格是人先给的，没有规格的域它管不到。作者自己写明：这个表述是 resource-unaware，**不覆盖 LLM 调用、token 和 wall-clock 预算**。另外它的 Learn 阶段用 GRPO 改模型权重，跨界到模型层，所以我们把它当形式化保证的对照，而不是纯 harness 方案。」

- 出处：`notes/skim/arxiv-2603.25111.md`（Theorem 5.4 + 局限原话）；`p3/severa-brief.md` 问 5
- 不要加的一句：「零违规说明它更安全」。

## 4. 预判追问（5 条，各 15 秒）

| 追问 | 回答要点 |
|---|---|
| 分类依据是什么？为什么是五轴？ | A/B/C/D/E 分别回答「改什么、凭什么改、怎么搜、有什么保证、递归到哪层」；五轴是工作假设，精读的任务之一就是推翻或修正它（`notes/AXES.md`） |
| 会不会只是 benchmark 过拟合？ | 这正是 Q1；我们看的是有没有 hold-out、有没有报尝试次数 N 的分布，而不是只看最好分数 |
| harness 自改进和 prompt 优化有什么区别？ | 改进产物是否参与下一轮改进；纯 prompt 优化不满足递归定义，只在边界外作背景（`group/domain-map.md` §4） |
| 这些方法的算力成本怎么算？ | 分搜索 / 更新 / 推理三段记录；缺项标「未找到」，只比较同口径的分母；RHO 是唯一给出 agent calls 对照的 |
| 为什么不包含模型 / 数据层面的自进化？ | 本组只做 harness 层；模型与数据自进化是另外两个同层次方向，混在一起会让「改什么」失焦 |
